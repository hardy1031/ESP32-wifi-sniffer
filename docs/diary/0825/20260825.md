# Embedded/IoT Security 方向性決め — 2週間プラン

_Created: 2026-08-25_

## 背景

Securityの中でもembedded/IoT系に興味があるが、以下がまだ未検証:
- 本当にembedded systemが好きか
- 実力的にこの分野をやっていけるか
- 大学院でIoT securityを研究テーマにできるか（研究として成立するか）

現時点の結論: 座学と自身で判断できる基準もないまま研究テーマを決めるのは希望的観測になるため、
まず2週間、個人プロジェクトで「好きか」「できるか」を見極める。目的は将来的にはportfolio/resumeと
興味の見極めの両立が理想だが、両立できなければ「好きかどうかを見極める」ことを優先する。

ハードウェア・低レイヤの実力: ほぼ未経験。

---

## 前半(4〜5日): 座学で全体地図を掴む

目的は深い理解ではなく、「聞いたことがある」状態を作ること。

### レイヤー1: 全体地図（半日〜1日）
- OWASP IoT Top 10 を読む。IoTセキュリティが扱う脅威領域（弱い認証、安全でない生態系インターフェース、firmwareの問題、物理的セキュリティ不足など10項目）の地図を掴む
- 参考: [OWASP Firmware Security Testing Methodology](https://scriptingxss.gitbook.io/firmware-security-testing-methodology)

### レイヤー2: 組み込みシステムの基礎語彙（1〜2日）
- マイコン、UART/SPI/I2C/JTAGなど通信インターフェースが何かを知る
- 参考: [Embedded-Engineering-Roadmap (GitHub, m3y54m)](https://github.com/m3y54m/embedded-engineering-roadmap)
- ここを飛ばすとレイヤー3・4（firmware吸い出し、ハードウェア攻撃）の話がつながらなくなる

### レイヤー3: firmware解析（1〜2日、座学＋軽い手動かし）
- ツール: **binwalk**（firmwareからファイルシステムを抽出）、**Ghidra**（NSA製・無料の逆アセンブラ）
- 練習台: **OWASP IoTGoat**（脆弱性入りのfirmwareイメージ。実機を買わずに練習できる）
- 参考: [Firmware RE with Binwalk and Ghidra · Steven Foerster](https://stevenfoerster.com/tutorials/firmware-extraction-and-reverse-engineering-with-binwalk-and-ghidra/)

### レイヤー4: 無線プロトコルのセキュリティ／ハードウェア攻撃とは何か（1〜2日、座学中心）
- 無線プロトコルのセキュリティ = BLE/Zigbee/WiFiなど、デバイス間の無線通信の暗号化・認証の弱さを突く分野（例: ペアリング時の平文通信の傍受）
- ハードウェア攻撃 = チップに物理的にアクセスして情報を抜く分野（UART/JTAG経由のデバッグポート侵入、電源を不安定にして誤動作させる「グリッチング」、チップを開けて中身を読むなど）
- 参考:
  - [Beginner's Guide to IoT and Hardware Hacking - TCM Security](https://academy.tcm-sec.com/p/beginner-s-guide-to-iot-and-hardware-hacking)（有料、体系的）
  - [jandress/IoT_resources (GitHub, リンク集)](https://github.com/jandress/IoT_resources)
  - [Top 12 Resources for IoT Security and Hardware Hacking (Medium, Vulfosec)](https://vulfosec.medium.com/top-12-resources-for-iot-security-and-hardware-hacking-fa0d8c8d7e0a)

## 後半(残り日数): 実際に手を動かすproject

座学で地図が分かった状態で、以下のいずれかを選んで着手する。

### 選択肢A: ESP32ベースのIoTデバイスを自作し、自分で攻撃する
- 内容: ESP32やRaspberry Pi PicoでシンプルなIoTデバイス（センサー計測 → WiFi/BLEで送信、など）を自作 → 完成後、自分でfirmwareを吸い出して解析、通信を傍受する
- カバー範囲: 「組み込み開発自体」＋「firmware解析」の両方。無線プロトコル（BLE/WiFi）にも自然に触れる
- 未経験でも情報量が多い（ESP32は世界的に情報が豊富なマイコンの一つ）
- 弱点: ハードウェア攻撃（JTAG/UART経由の物理アクセス、グリッチングなど）はほぼ体験しない

### 選択肢B: 既製の安いIoTデバイス(中古の監視カメラ、スマートプラグなど)を解析する
- 内容: 分解してUART/JTAGを探し、firmwareを吸い出し、binwalk/Ghidraで解析、既知の脆弱性や設定ミスを探す
- カバー範囲: firmware解析＋ハードウェア攻撃（物理的にチップやピンを触る）の両方
- 弱点: 「組み込み開発自体」は体験しない。未経験だとUART/JTAG特定の初手でかなり詰まる可能性がある

### 判断基準（2週間後）
- 未定。「最初のprojectが終わったらそこでまた考える」というスタンス。判断基準自体は今後詰める必要がある。
