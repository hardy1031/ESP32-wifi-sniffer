_Created: 2026-08-26_

## OWASP IoT Top 10 と FSTM は別物

- **OWASP IoT Top 10**: IoTデバイスによくある脆弱性の「カテゴリ一覧」
- **FSTM (Firmware Security Testing Methodology)**: ファームウェア1つを対象にした「調査手順」（情報収集→入手→解析→ファイルシステム抽出→静的解析→エミュレート→動的解析→ランタイム解析→バイナリ悪用の9段階）
- 関係性: FSTMで見つけた脆弱性が、結果的にTop 10のどれかに分類される

## IoT Top 10、2014年版と2018年版

2014年版(I1〜I10)は汎用的なWeb/ネットワークセキュリティ項目とIoT固有項目が混在していた。2018年版で整理され、IoT固有ドメインの比重が増した。

- 汎用項目(Web/APIセキュリティの知識で対応可能): 認証、暗号化、プライバシー、クラウド/モバイルインターフェース
- **IoT固有項目**:
  - I2 Insecure Network Services（組込み系プロトコル、後述）
  - I4 Lack of Secure Update Mechanism（ファームウェアOTA、FSTMの対象領域）
  - I8 Lack of Device Management（2018年版で新規追加。フリート運用・パッチ管理）
  - I9 Insecure Default Settings
  - I10 Lack of Physical Hardening（物理攻撃）

→ 学習の投資先は「I2(組込みプロトコル)・I4/I9(ファームウェア)・I10(物理)」の3ドメインに絞れる。他はWeb/ネットワークセキュリティの応用。

## IoTデバイスのアップデート機構

「OSがないから自分でアップデートできないのでは」という疑問への回答:

- 組込みデバイスにも大抵OS/ランタイムはある。高性能側は組込みLinux、低性能側(MCU)はFreeRTOS/Zephyr等のRTOS、またはbare-metal。ネットワークスタック自体は持っていることがほとんど。
- **Pull型が主流**: デバイスがoutboundでアップデートサーバーに定期的に問い合わせ、新バージョンがあればダウンロード。NAT/ファイアウォールの内側にいることが多く、外から直接pushで到達できないため。
- **Push型に見えるものもハイブリッド**: MQTT等でサーバーが「アップデートあるよ」と通知(publish)し、デバイス側が受けて自分でpullする。真の意味で認証なしにファイルを押し込む方式は稀（それ自体が脆弱性になる）。
- ローカルネットワーク限定のデバイスは、スマホアプリがローカル経由で直接pushすることもある。

## RTOS (Real-Time Operating System)

- 「決められた時間内に必ず処理を終える」ことを保証するOS。普通のOS(Linux/Windows)は速さ重視だがタイミング保証はない。
- 組込みで使われる理由: リソースが非力（KB〜数MB RAM）で軽量、かつセンサー割り込みやモーター制御など締切のある処理が多いため。
- 代表例: FreeRTOS, Zephyr, Mbed OS, VxWorks
- セキュリティ観点: メモリ保護機構が弱い/無いものが多く、buffer overflowが即コード実行につながりやすい。

## Insecure Network Services とネットワーク越しのbuffer overflow

「ネットワーク経由でbuffer overflowがどう起きるか」のイメージ:

1. デバイスが何らかのネットワークサービス(HTTP, Telnet, 独自プロトコル等)を待ち受けている
2. サービスの実装(大抵C)が受信データをサイズチェックせず固定長のスタック上バッファにコピーする(`strcpy`等)
3. 攻撃者がバッファサイズを超えるデータを送る
4. はみ出した部分がスタック上の隣接領域＝リターンアドレスを上書きする
5. 関数がreturnする際、上書きされたアドレスに処理が飛ぶ → 任意コード実行

- 「ネットワーク越し」とは物理的操作ではなく、単にそのポートに対してTCP/UDPパケットを送るだけ。ローカルの入力(引数・ファイル)を突く攻撃と原理は同じで、入力元がソケットの`recv()`であるだけ。
- IoTデバイスは危険な関数(strcpy/sprintf)を使いがちでファジングの機会も少なく、この種の脆弱性が多い。

### stackとbufferの関係

- **stack**: 関数呼び出しごとにローカル変数・引数・戻り先アドレスを積むメモリ領域。関数を抜けると自動的に片付く。
- **buffer**: 「データを一時的に貯める領域」を指す一般名詞（stack/heap/globalどこにでも置ける）。
- **スタック上バッファ**: 関数のローカル変数として確保された配列(`char buffer[64]`など)。関数の直後にリターンアドレスが積まれているため、オーバーフローさせるとそこを書き換えられる。ヒープ上バッファの場合は隣にリターンアドレスがなく、別の悪用手法が必要になる。

### port scan と fuzzing

- **port scan**: 1〜65535番ポートに接続を試み、開いているポート＝動いているサービスを一覧化する（nmapなど）。攻撃の第一歩、対象の地図作り。
- **fuzzing**: 見つけたサービスに大量のランダム/異常/境界値データを自動送信し、クラッシュ等の異常動作を検出する手法。クラッシュ箇所を人間が精査し、単なるクラッシュかbuffer overflow等の悪用可能な脆弱性かを判断する。
- 代表ツール: AFL, boofuzz, Peach Fuzzer（FSTMステップ7「Dynamic analysis」に該当）
